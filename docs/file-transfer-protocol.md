# Explicit file transfer protocol, version 1

All methods use the existing pinned mutual TLS connection. The receiver checks its local `FileSystem` grant for every request. Paths are UTF-8 JSON strings; file bytes are raw stream frames. The remote path is interpreted on the receiver, with a leading `~` expanded to the receiver user's home directory. Paths are limited to 4096 characters. Symbolic links and reparse points are rejected in this initial transfer implementation. The caller must explicitly request overwrite; the default is to fail if the destination exists.

- RPC `file.stat`: request JSON `{ "path": "..." }`; response JSON `{ "kind": "file|directory", "length": 123, "lastWriteUnixMs": 123 }`.
- RPC `file.list`: request JSON `{ "path": "...", "offset": 0 }`; response JSON `{ "entries": [{ "name": "...", "kind": "file|directory", "length": 123, "lastWriteUnixMs": 123 }], "hasMore": false }`. Entries are ordered by ordinal filename; at most 128 per page. Listing a changing directory may require restarting the copy.
- RPC `file.mkdir`: request JSON `{ "path": "..." }`; empty response. Creates missing parent directories, but fails if the target is a non-directory.
- RPC `file.put.open`: request JSON `{ "path": "...", "overwrite": false, "lastWriteUnixMs": 123 }`; response is a nonzero 4-byte big-endian transfer ID. The receiver opens a unique temporary file in the target directory. The destination is untouched until commit.
- Client `StreamData`, method `file.put.data`, `RequestId = 0`, `StreamId = transferId`: up to 64 KiB of raw bytes per frame. Client `StreamEnd` with the same method and ID signals all bytes were sent.
- RPC `file.put.commit`: 4-byte big-endian transfer ID. The receiver flushes and closes the temporary file, sets the requested timestamp where possible, and atomically renames it into place according to the overwrite flag. Response is an 8-byte big-endian signed byte count. A failed/cancelled/disconnected transfer removes its temporary file.
- RPC `file.get.open`: request JSON `{ "path": "..." }`; response is transfer ID (4 bytes), file length (8-byte signed big-endian), and last-write Unix milliseconds (8-byte signed big-endian). The receiver starts streaming `file.get.data` frames (up to 64 KiB), then `StreamEnd`, all with `RequestId = 0` and `StreamId = transferId`. Output can arrive before the open response, so the caller buffers a bounded amount until it knows the ID. The receiver closes the file and removes its transfer state at EOF.
- RPC `file.get.close`: 4-byte big-endian transfer ID, empty response. Cancels a download when the caller stops early. A normal completed download needs no close request.

Transfer IDs are unique and nonzero within one connection. At most eight transfers may be active per connection. The CLI writes downloads to a local temporary file and renames only after the complete stream arrives. Directory copies traverse entries recursively; no symlink traversal. `xas cp` sends progress to stderr and returns a nonzero exit code on failure. Mounting remains a separate future feature.
