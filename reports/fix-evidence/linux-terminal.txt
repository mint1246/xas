Linux interactive terminal investigation
========================================

Cause
-----
The Linux interactive clients previously passed Console.OpenStandardInput() after setting the terminal to raw mode. .NET 10.0.10's Unix Console implementation wraps an attached stdin in an interactive line-reading stream, which applies console line/echo handling and therefore conflicts with raw terminal mode. In a PTY reproduction this yielded local echo and withheld input until line completion. The fix duplicates fd 0 and wraps the duplicate directly, bypassing Console's line-reading layer. The duplicate is owned and disposed by each interactive client.

The terminal-size loop also used `stty size` subprocesses. It now uses ioctl(TIOCGWINSZ), which reads dimensions without launching a process or touching terminal mode. The raw input pump is started on the thread pool because a synchronous Unix fd can block during ReadAsync before its first await; this keeps the protocol event loop live.

Evidence
--------
Built a standalone Linux x64 PTY probe by linking the production TerminalMode.cs into tests/Terminal.PtyProbe. Ran it in the existing KVM-Linux-Build WSL distro; no daemon/service was started.
